VL.Mapsui 节点逐行精读

七课，从 7 行的 CenterOn 读到要管网络连接的 OpenStreetMap。每一课多讲一个新模式，前面讲过的写法后面不再重复。左边是真实源码，像在编辑器里一样连成一整块；带编号的行在右边有解释，难的地方附 JS 写法。鼠标移到解释上，左边对应的行会亮起来；点代码行，右边跳到它的解释。

打开后只剩编号，解释先藏起来；你自己读那一行，再点编号对答案。

长段的 /// 文档注释折叠成一行，写明它讲什么。原文就是 vvvv 里鼠标悬停时显示的说明，可以在源文件里读全文。

先修课

0 · vvvv 怎么调用你写的类

先看一件真东西。vvvv 打开 patch 时，会把整张图翻译成 C# 再编译。下面几行摘自 HowTo Show a map 生成的 C#（tools\Compile-HelpPatches.ps1 -KeepOutput 可以留下这个文件），一共 375 行。长的行用 … 省略了一部分参数。看懂这几行，你就知道后面每个节点的 Update 是被谁、在什么时候调用的。

记住这张对照：process 节点在 Create 里 new 一次，之后每帧调用它的 .Update(...)；static 节点没有对象，每帧直接用类名调用。我们的检查器 Compile-HelpPatches.ps1 做的就是读这个文件，确认 new ...Node() 出现在 Create 里，而不是在 Update 里。

新模式：static 节点 = 每帧调用的纯函数

1 · CenterOn：最简单的节点

src/VL.Mapsui/NavigateNodes.cs · 第 22–34 行，再加第 155–159 行

想一想：CenterOn 每帧都执行。如果你把它接上，地图就会每帧被拉回这个点，鼠标拖也拖不动。HowTo Set the view 里写的 “Wired every frame they PIN the view” 说的就是这个。所以用鼠标拖地图要用下一课这种会“记事”的节点。

新模式：用一个字段记住上一帧

2 · ZoomIn：只在“刚按下”那一帧干活

src/VL.Mapsui/ZoomInNode.cs · 全文 46 行

第 37 行的判断，按帧看

假设你把一个 Toggle 接到 Trigger，并让它保持按下几帧：

帧trigger（这一帧）_was（上一帧）trigger && !_was结果
1falsefalsefalse不动
2truefalsetrue放大一级
3truetruefalse不动（还按着）
4truetruefalse不动
5falsetruefalse不动（松开了）
6truefalsetrue再放大一级

如果没有 _was，第 2、3、4 帧都会放大，一秒放大 60 级，每一级都让图层去下载瓦片。这个字段防的就是这种失控。

新模式：几个字段组成一个小状态机

4 · OpenStreetMap：一个会联网的节点

src/VL.Mapsui/OpenStreetMapLayerNode.cs · 全文 192 行，代码约 60 行

这是整个包里最需要小心的节点：它会发 HTTP 请求，会往硬盘写文件。前面三课的写法这里都会用到，再加上两件新事：谁来释放资源，以及哪些东西能重建、哪些不能。

这一课的要点，一句话：Update 每帧都会被叫到，但第 118 行的 if 让它几乎永远什么都不做；真要重建时（第 121 行），也只重建便宜的图层，昂贵的瓦片源（第 141 行）一辈子只建一次。

新模式：lambda 回调，以及“只读一次”的 pin

5 · Map：一张活得比输入还久的地图

src/VL.Mapsui/MapNode.cs · 第 26–121 行

一条连起来的保证：第 84 行逐个按身份比较图层能成立，靠的是上游 OpenStreetMap 节点每帧交出同一个图层对象（第 4 课第 128 行）。Map 自己也每帧交出同一个 _map（第 109 行），于是下游 ToSkiaLayer 也不用重建。整个包的节点就是这样一环扣一环：每一环都保证“输入没变，就交出同一个对象”。

新模式：按内容比较，而不是按身份

6 · FeatureLayer：你的数据怎么上地图

src/VL.Mapsui/FeatureLayerNode.cs · Update（第 69–132 行）和两个比较函数（第 144–174 行）

上一课说每一环都交出同一个对象。但 FeatureLayer 的上游是 VL.NetTopologySuite 的 Feature 节点，它是静态节点，每帧都会返回一个新对象，内容却完全一样。这条链在这里断了，所以 FeatureLayer 必须自己按内容判断“变没变”。

文件里还有两个函数没逐行讲：Describe（第 200 行起）负责生成 Status 那句提示，ToMapsui 把一个 NTS 要素换成 Mapsui 要素，经纬度转成米。读懂了前面这些，它们只是同样写法的重复。

练习

7 · 轮到你：如果要写一个新节点

写之前，docs/RULES.md 要求按顺序问三个问题：

  1. 用现有的三个节点在 patch 里连一下就能做到吗？能的话，它该是一个帮助 patch，不该是新节点。
  2. 它持有资源吗？连接、文件、缓存、图层，或者需要记住上一帧？是的话写成 [ProcessNode]，否则写成 static 方法。
  3. 它替用户做的决定，用户在乎吗？在乎的话，就做成一个 pin 让用户自己定。

还有一条硬指标：输入 pin 以三个为目标，四个要有理由，五个说明一个节点里塞了两个决定。

题目

假设要做一个 PanEast 节点：每按一下按钮，地图中心往东移 1 度。先想三件事：它该是 static 还是 process？需要几个字段？大概怎么写？想好了再展开答案。下面的代码只是练习答案，包里没有这个节点。

展开参考答案

process 节点，因为要只在“刚按下”那一帧动一次，所以和 ZoomIn 一样需要记住上一帧（第 2 课）。它不持有网络或文件，所以不需要 IDisposable。

[ProcessNode(Name = "PanEast", Category = "Mapsui.Navigate")]
public class PanEastNode
{
    bool _was;                                    // 上一帧的 trigger

    public Map Update(Map map, bool trigger = false, double degrees = 1.0)
    {
        if (map is null) return map!;

        if (trigger && !_was)                        // 只在刚按下那一帧
        {
            var v = map.Navigator.Viewport;      // 现在的中心，单位是米
            var (lon, lat) = SphericalMercator.ToLonLat(v.CenterX, v.CenterY);
            NavigateNodes.CenterOn(map, lon + degrees, lat);   // 复用第 1 课的静态节点
        }
        _was = trigger;                          // 一定写在 if 外面
        return map;                              // 交出同一个 map，方便串联
    }
}

三个输入 pin（Map、Trigger、Degrees），没超标。degrees 做成 pin，是因为“一次移多少”是用户在乎的决定（第 3 问）。真要加进包里的话，还要补测试（参照 ZoomIn 的测试用 Zooms 计数）、补一个帮助 patch 并标上 F1，再更新 Compile-HelpPatches 和 Test-VLPatch 里的节点表。

总结：判断“变没变”的三种方法

七课读下来，这个包里所有的 if 几乎都在回答同一个问题：“这一帧的输入和上一帧一样吗？”问法只有三种：

按身份 · ReferenceEquals

“还是同一个对象吗？”最快。用在上游保证会交出同一个对象的地方：缓存（第 4 课 118 行）、样式（第 6 课 118 行）、地图（ToSkiaLayer）。

逐个按身份 · SequenceEqual

“列表里每个位置还是同一个对象吗？”用在图层列表（第 5 课 84 行）。列表对象不保证是同一个，但里面的图层是。

按内容 · EqualsExact + 属性

“内容还一样吗？”最慢，但上游每帧都给新对象时只能这样比：NTS 的要素（第 6 课 110 行）。

选错了会怎样：该按内容比的地方按身份比，每帧都会重建，地图会闪（FeatureLayer 曾经就是这样）；该按身份比的地方按内容比，也能工作，只是白白浪费计算。
